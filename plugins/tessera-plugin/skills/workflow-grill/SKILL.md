# Навык workflow-grill

Обёртка запуска операции `workflow`: принимает требование владельца одним вызовом, строит
предмет-адрес прогона и делегирует порождение и исполнение навыкам плагина backlog. Сам навык
не порождает беклоги, не пишет шаблоны и не исполняет задачи — всё это делают навыки
`backlog-generate` и `backlog-run` плагина backlog.

## Вход

Вход навыка — требование владельца: что нужно сделать, текстом вызова.

- Требование названо — навык не спрашивает его повторно.
- Вызов пуст — навык задаёт ровно один вопрос «какое требование» и после ответа продолжает
  без повторных вопросов о недостающем вводе.

---

## Порядок

1. **Проверить зависимости** — навыки `backlog-generate`, `backlog-run` и `grilling` доступны
   в текущем харнесе под коротким именем либо под именем с префиксом плагина
   (`/backlog:backlog-generate`, `/backlog:backlog-run`, `/mattpocock-skills:grilling`).
   Зависимости на месте — навык продолжает работу без вопросов об установке; хоть одного
   нет — отказ раздела «Отказы» с командой установки.
2. **Принять требование** — по правилам раздела «Вход».
3. **Построить предмет прогона** — строку `{YYYYMMDDHHMMSS}-{краткое_описание_на_анг}`:
   штамп `date +%Y%m%d%H%M%S` локального времени в момент вызова и слаг из 2–5 английских слов
   через дефис по смыслу требования. Предмет — адрес прогона, исходная формулировка требованиям
   не адрес; коллизию адреса штамп делает практически невозможной.
4. **Предложить `target`** — репозиторий из `git remote get-url origin` текущего проекта,
   приведённый к виду `owner/repo`. Навык предлагает значение сам, вопрос «какой репозиторий»
   не задаётся.
5. **Выбрать каталог шаблонов** — шаблон операции приоритетнее поставленного:
   - в проекте есть `templates/workflow.md` — навык передаёт каталог `templates` проекта;
   - своего шаблона нет — навык передаёт поставленный с плагином: `../../templates` от каталога
     этого файла, разрешённый через `realpath`, — харнесу навык доступен через симлинк, и путь
     без разрешения укажет мимо.

   ```bash
   realpath "$(dirname <путь к этому SKILL.md>)/../../templates"
   ```

6. **Вызвать `backlog-generate`** с операцией `workflow`, предметом из шага 3, значениями
   `target` и `requirement` (исходная формулировка владельца) и каталогом из шага 5. Собранный
   вызов `backlog generate` показывается владельцу целиком до прогона — предмет и слаг правятся
   при подтверждении.

   ```bash
   backlog generate --operation workflow --subject {предмет} --value target={owner/repo} \
     --value requirement="{требование}" --templates {каталог из шага 5}
   ```

## Передача исполнения

Вызов этого навыка — заранее данный ответ «исполнить». После успешного порождения навык передаёт
исполнение `backlog-run` без повторного вопроса «исполнить либо остановиться».

Ветка изменений и коммиты целевого репозитория — по правилам
[`git-rules`](../../rules/git-rules.md): формат сообщения коммита — `GIT-009`, коммит и push —
только по явному запросу владельца — `GIT-015`.

Стоп-знак перед необратимой задачей шаблона (создание задачи на GitHub) сохраняется и спрашивает
владельца всегда — он принадлежит шаблону и исполнителю, обёртка его не снимает.

## Отказы

Отказы передаются владельцу как есть, навык не разбирает их сам и не заводит шаблон:

- навыки `backlog-generate` и `backlog-run` недоступны в харнесе — навык не запускается:
  владельцу сообщается одна команда установки поставки полным профилем и ход останавливается;
- навык `grilling` недоступен в харнесе — навык не запускается: владельцу сообщается та же
  команда установки поставки полным профилем и ход останавливается;

  ```bash
  curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --profile full
  ```

- шаблона операции нет ни в проекте, ни в поставке плагина — отказ `backlog-generate`;
- порождение не удалось — ввод, дефект шаблона, окружение — отказ `backlog-generate`
  по его таблице исходов;
- адрес занят лежащим беклогом — вопрос «исполнить лежащий либо породить с новым предметом»
  решает владелец.
