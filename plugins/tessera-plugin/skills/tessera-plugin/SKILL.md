## Правила

Точка входа к правилам фреймворка: назовите код (`DOC-014`, `READ-004`) или тему — навык
называет правило и путь, применяет его к задаче.

| Тема | Правило |
|------|---------|
| Документы и их оформление | [`documentation-rules.md`](../../rules/documentation-rules.md) |
| Чтение документов, границы контекста задачи | [`reading-rules.md`](../../rules/reading-rules.md) |
| Окружение: mise, сервисы, переменные | [`environment.md`](../../rules/environment.md) |
| Архитектура слоёв, SOLID, модули | [`clean-architecture.md`](../../rules/clean-architecture.md) |
| Контракты чтения и записи | [`cqrs.md`](../../rules/cqrs.md) |
| Домен: контексты, агрегаты, события | [`ddd.md`](../../rules/ddd.md) |
| Документы для людей: README, CONTRIBUTING, кейсы | [`project-docs-rules.md`](../../rules/project-docs-rules.md) |
| Плагины: потоки поставки и зависимостей, предмет описания | [`software-class-rules.md`](../../rules/software-class-rules.md) |
| Ветки, коммиты, границы git | [`git-rules.md`](../../rules/git-rules.md) |

Профильные навыки ссылаются на свои правила сами. Правила применяются двумя путями: в проекте,
куда скрипт поставки подключил правила в области `--scope project` (копии в `.tessera/rules/`,
секция в `AGENTS.md` проекта), — их предписывает секция правил; везде прочее — через навыки.
Хуков нет — универсальность важнее автозагрузки.

## Зависимости

Зависимости плагина — артефакты потока зависимостей, без которых навыки плагина не работают;
лаунчер `backlog` — CLI зависимости formular и в состав плагина не входит. Навык `workflow-fast`
требует навыки `backlog-generate` и `backlog-run` плагина backlog; `workflow-grill` —
дополнительно навык `grilling` плагина mattpocock-skills. Зависимости — опциональная поставка:
их приносят компоненты состава, который задаёт `--components`: formular — для `workflow-fast`,
formular и mattpocock-skills — для `workflow-grill`. Без `--components` скрипт ставит все
компоненты; состав ставится точно — поставленное вне перечня снимается. Навык проверяет
зависимость первым шагом, и её отсутствие останавливает его отказом с одной командой установки
состава.

## Подключение

Поставка — скрипт `scripts/install.sh`: одной командой без клона либо запуском из клона.
Он раскладывает источники в хранилище и связывает навыки симлинками с каталогами навыков
найденных харнесов. Состав задаёт `--components`, без него ставятся все компоненты; область
установки — `--scope project|user` (умолчание `user`); в области project правила подключаются
к проекту: копии в `.tessera/rules/` и секция в `AGENTS.md` — состав правил выбирают параметром
`--rules` или в диалоге. Машиночитаемый реестр поставки печатает `scripts/install.sh --registry`
— JSON: каждая запись называет имя, тип, целевой путь и источник; установка записывает тот же
реестр файлом `registry.json`. Состав, область и правила печатает `scripts/install.sh --help`,
шаги установки — корневой `README.md` репозитория tessera.
