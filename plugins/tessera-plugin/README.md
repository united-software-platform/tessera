# tessera-plugin

Носитель навыков, правил и шаблонов операций проекта tessera: навыки формата Agent Skills,
правила оформления и процесса, шаблоны workflow-операций. Каталог `skills/` — единый источник
для любого харнеса, читающего навыки; плагин с манифестами — адаптер для харнесов
с маркетплейсами. В плагине только навыки, правила и шаблоны: инструментов — хуков, команд,
MCP-серверов — в нём нет; плагины-зависимости приносит скрипт поставки
(см. [Зависимости](#зависимости)), а не плагин.

## Структура

| Путь | Назначение |
|------|------------|
| `.zcode-plugin/plugin.json` | Манифест плагина для ZCode |
| `.claude-plugin/plugin.json` | Зеркальный манифест для Claude Code; синхронизируется с ним |
| `skills/` | Навыки формата Agent Skills — по каталогу на навык |
| `rules/` | Правила оформления и процесса: документация, чтение, окружение, архитектура, CQRS, DDD, документы проекта, git |
| `templates/` | Шаблоны операций `workflow-fast` и `workflow` — из них `backlog generate` порождает беклог |

Навыки:

| Навык | Назначение |
|-------|------------|
| `tessera-plugin` | Навык-каталог: состав плагина, зависимости, подключение |
| `project-docs` | Аудит и правка `README.md`, `CONTRIBUTING.md` и документа кейсов по DGN-норме |
| `workflow-fast` | Быстрый рабочий процесс от требования до ветки изменений без прожарки |
| `workflow-grill` | Рабочий процесс от требования до прожарки |

Навык `workflow-fast` зависит от плагина backlog, `workflow-grill` — от backlog
и mattpocock-skills; см. [Зависимости](#зависимости).

## Зависимости

| Зависимость | Минимальная версия | Репозиторий-источник |
|-------------|--------------------|----------------------|
| `backlog` | 1.4.0 | `https://github.com/united-software-platform/formular.git`, путь `plugin/backlog`, ветка `main` |
| `mattpocock-skills` (навык `grilling`) | 1.3.2 | `https://github.com/mattpocock/skills.git`, корень репозитория, ветка `main` |

Зависимости — опциональная поставка: их ставит скрипт поставки `scripts/install.sh`
по профилю. Профиль `backlog` приносит backlog для `workflow-fast`, полный добавляет
mattpocock-skills для `workflow-grill`; профиль «только tessera» обходится без них. Скрипт
клонирует репозитории-источники в хранилище `~/.local/share/tessera/`, связывает их навыки
симлинками с каталогами навыков харнесов и ставит команду `backlog`. Состав профилей печатает
`scripts/install.sh --help`.

Навык проверяет зависимость первым шагом — по короткому имени (`backlog-generate`, `grilling`)
и по имени с префиксом плагина (`/backlog:backlog-generate`, `/mattpocock-skills:grilling`).
Без зависимости навык останавливается отказом с одной командой запуска скрипта.

## Совместимость с харнесами

Единый источник без привязки к конкретному харнесу:

- **Каталог `skills/`** — исходная точка для любого харнеса, читающего навыки из каталога.
  Поставка — скрипт `scripts/install.sh`: он находит установленные харнесы и связывает навыки
  симлинками с их каталогами навыков; для харнеса вне таблицы принимается путь к его каталогу.
  Основной путь установки — в корневом [`README.md`](../../README.md) репозитория, перечень
  харнесов и параметров — в `scripts/install.sh --help`.
- **Плагин — адаптер** для обновления кнопкой в харнесах с маркетплейсами: ZCode читает
  `.zcode-plugin/plugin.json`, Claude Code — `.claude-plugin/plugin.json`; содержимое
  идентично и правится совместно. Плагин приносит только навыки и правила tessera: навыки
  workflow без зависимостей останавливаются отказом с командой скрипта —
  [кейс 3](../../docs/use-cases.md#кейс-3-хочу-обновлять-tessera-кнопкой) документа кейсов.
- **Каталог маркетплейса** — `.claude-plugin/marketplace.json` в корне репозитория:
  расположение Claude Code, поддерживаемое и ZCode; имя маркетплейса `tessera`, владелец
  `usp` — как у formular. Маркетплейс добавляется git-URL репозитория целиком.
- **Правила для работы в репозитории** индексирует корневой `AGENTS.md` — стандарт, читаемый
  харнесами без поддержки плагинов (Codex, opencode и другими).
- **Правила в проекте потребителя** — скрипт поставки с параметром `--project` копирует
  выбранные правила в `.tessera/rules/` проекта и ведёт секцию правил в его `AGENTS.md`;
  состав правил выбирают параметром `--rules` или в диалоге, повторный запуск обновляет
  секцию и копии, `--uninstall --project` снимает их.
- **Сам репозиторий потребляет собственные навыки**: локальная настройка
  `scripts/bootstrap.sh` создаёт симлинки в каталогах харнесов на `skills/` плагина — работа
  в репозитории идёт с тех же версий, что получает внешний потребитель. Каталоги регистрации
  находятся вне индекса git: их содержимое разработчик выбирает сам.

## Как расширять

1. Новый навык — каталог `skills/<имя>/SKILL.md` с frontmatter `name` и `description`;
   подхватывается обоими манифестами автоматически.
2. Новое правило — файл в `rules/` и строка в перечне корневого `AGENTS.md`; правило
   подключается к проектам без правки скрипта: перечень правил скрипт берёт из клона,
   а не из своего текста.
3. При изменении поведения повышайте `version` в `.zcode-plugin/plugin.json` **и**
   `.claude-plugin/plugin.json` по семантическому версионированию.

## Проверка

Скрипт поставки завершается самопроверкой: каждая созданная ссылка разрешается в `SKILL.md`,
а `backlog --help` через лаунчер отвечает успехом. При подключённых правилах самопроверка
сверяет каждую ссылку секции правил с файлом копии в проекте и каждую записанную копию —
с источником. Отчёт установки называет результат каждой проверки; при неисправной ссылке
или копии скрипт завершается ненулевым кодом.

Манифесты не расходятся:

```bash
diff plugins/tessera-plugin/.zcode-plugin/plugin.json plugins/tessera-plugin/.claude-plugin/plugin.json
```

Пустой вывод — манифесты идентичны.
