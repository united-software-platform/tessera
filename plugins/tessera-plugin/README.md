# tessera-plugin

Носитель навыков и правил проекта tessera: навыки формата Agent Skills и правила оформления
и процесса. Каталог `skills/` — единый источник для любого харнеса, читающего навыки;
плагин с манифестами — адаптер для харнесов с маркетплейсами.

## Структура

| Путь | Назначение |
|------|------------|
| `.zcode-plugin/plugin.json` | Манифест плагина для ZCode |
| `.claude-plugin/plugin.json` | Зеркальный манифест для Claude Code; синхронизируется с ним |
| `skills/` | Навыки формата Agent Skills — по каталогу на навык |
| `rules/` | Правила оформления и процесса: документация, чтение, окружение, архитектура, CQRS, DDD, документы проекта, git |

Навыки:

| Навык | Назначение |
|-------|------------|
| `tessera-plugin` | Навык-каталог: состав плагина, зависимости, подключение |
| `project-docs` | Аудит и правка `README.md`, `CONTRIBUTING.md` и документа кейсов по DGN-норме |
| `workflow-fast` | Быстрый рабочий процесс от требования до ветки изменений без прожарки |
| `workflow-grill` | Рабочий процесс от требования до прожарки |

Навык `workflow-fast` зависит от плагина backlog, `workflow-grill` — от backlog
и mattpocock-skills; см. [Зависимости](#зависимости).

## Зависимости

| Зависимость | Минимальная версия | Источник |
|-------------|--------------------|----------|
| `backlog` | 1.4.0 | `https://github.com/united-software-platform/formular.git`, путь `plugin/backlog`, ветка `main` |
| `mattpocock-skills` (навык `grilling`) | 1.3.2 | `https://github.com/mattpocock/skills.git`, корень репозитория, ветка `main` |

Нативной авто-установки зависимостей в формате плагинов нет — зависимости закрываются двумя
механизмами:

1. **Записи в том же маркетплейсе**: каталог `tessera` содержит записи `backlog`
   и `mattpocock-skills` с git-источниками — плагин и зависимости ставятся с одной страницы
   маркетплейса, версии подтягиваются актуальными с веток при его обновлении.
2. **Проверка при запуске**: навыки `workflow-fast` и `workflow-grill` первым шагом проверяют
   доступность `/backlog:backlog-generate`; `workflow-grill` дополнительно —
   `/mattpocock-skills:grilling`. При отсутствии — отказ с инструкцией установки.

Установка зависимостей — [кейсы 1 и 2](../../docs/use-cases.md) документа кейсов: записи
ставятся из того же маркетплейса, что и плагин; запасной путь — маркетплейсы formular
и mattpocock напрямую.

## Совместимость с харнесами

Единый источник без привязки к конкретному харнесу:

- **Каталог `skills/`** — исходная точка для любого харнеса, читающего навыки из каталога;
  универсальный путь подключения — в корневом [`README.md`](../../README.md) репозитория
  (клон и `scripts/bootstrap.sh`).
- **Плагин — адаптер** для харнесов с маркетплейсами: ZCode читает `.zcode-plugin/plugin.json`,
  Claude Code — `.claude-plugin/plugin.json`; содержимое идентично и правится совместно.
  Установка обновляемым плагином — в [документе кейсов](../../docs/use-cases.md).
- **Каталог маркетплейса** — `plugins/.claude-plugin/marketplace.json`: расположение
  Claude Code, поддерживаемое и ZCode; имя маркетплейса `tessera`, владелец `usp` — как
  у formular.
- **Правила для работы в репозитории** индексирует корневой `AGENTS.md` — стандарт, читаемый
  харнесами без поддержки плагинов (Codex, opencode и другими).
- **Сам репозиторий потребляет собственные навыки**: локальная настройка
  `scripts/bootstrap.sh` создаёт симлинки в каталогах харнесов на `skills/` плагина — работа
  в репозитории идёт с тех же версий, что получает внешний потребитель. Каталоги регистрации
  находятся вне индекса git: их содержимое разработчик выбирает сам.

## Как расширять

1. Новый навык — каталог `skills/<имя>/SKILL.md` с frontmatter `name` и `description`;
   подхватывается обоими манифестами автоматически.
2. Новое правило — файл в `rules/` и строка в перечне корневого `AGENTS.md`.
3. При изменении поведения повышайте `version` в `.zcode-plugin/plugin.json` **и**
   `.claude-plugin/plugin.json` по семантическому версионированию.

## Проверка

В окружении разработки доступна проверка манифеста перед установкой:

```bash
zcode plugins validate .
```

Команда выполняется из корня плагина; в обычной установке ZCode Desktop недоступна — там плагин
проверяется установкой из локального маркетплейса.
