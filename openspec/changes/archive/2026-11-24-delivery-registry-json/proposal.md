# Proposal

## Why

Состав поставки описан в `README.md` словами и перечнями имён, снятыми вручную: перечень
навыков зависимостей дрейфует за источниками, а какие имена и пути появятся в проекте и на
машине — и с чем они совпадут с уже установленным — видно только из отчёта после установки.
Потребителю нужен машиночитаемый реестр поставки, чтобы сверить его со своим репозиторием
до установки и проверить факт установки после неё.

## What Changes

- Скрипт поставки получает параметр `--registry`: печатает реестр поставки в JSON и
  завершается, ничего не устанавливая и не меняя на диске. Реестр отражает параметры запуска
  (`--profile`, `--project`, `--harness`, `--skills-dir`, `--rules`).
- Запись реестра — имя, тип (`symlink`, `copy`, `section`, `wrapper`), целевой путь и источник;
  реестр описывает компоненты с хранилищем, навыки, правила, секцию `AGENTS.md` и лаунчер.
- Установка записывает факт тем же реестром: `registry.json` в хранилище и, с `--project`,
  в `.tessera/` проекта; `--uninstall --project` снимает реестр проекта.
- Без клонов в хранилище реестр печатается частичным: уровни машины и проекта описаны, перечни
  зависимостей помечены как недоступные до получения источников.
- Перечни имён в `README.md` заменяются командой `--registry`; таблица уровней поставки
  остаётся.
- Версия плагина — 0.6.0.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `delivery`: добавляются требования «Реестр поставки печатается в JSON», «Запись реестра
  называет имя, тип, путь и источник», «Реестр отражает параметры запуска и не меняет диск»,
  «Реестр без источников печатается частично», «Установка записывает реестр как факт»;
  изменяются требования «Установка завершается самопроверкой» — отчёт называет путь
  записанного реестра — и «Удаление убирает созданное» — снятие реестра проекта.

## Impact

- Код: `scripts/install.sh` — параметр `--registry`, сборщик реестра с экранированием JSON
  средствами bash, запись `registry.json`, снятие при удалении. Новые инструменты не нужны:
  стороннего генератора JSON нет, `jq` не требуется.
- Проекты потребителей: с `--project` появляется `.tessera/registry.json`; хранилище получает
  `registry.json` рядом с клонами.
- Документы: `README.md` (перечни имён заменяются командой), `docs/use-cases.md` (кейс
  сверки реестра с репозиторием до установки), `plugins/tessera-plugin/README.md`,
  `CONTRIBUTING.md` (проверки), `GLOSSARY.md` (термин «Реестр поставки»).
- Вне изменения: другие форматы (TSV, YAML); схема и подпись реестра; реестры
  плагинов-зависимостей из их собственных манифестов.
