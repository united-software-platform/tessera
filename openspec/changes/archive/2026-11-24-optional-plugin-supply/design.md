# Design

## Context

Зависимости навыков `workflow-fast` и `workflow-grill` закрываются двумя механизмами
(README плагина, «Зависимости»): записи `backlog` и `mattpocock-skills` в каталоге
маркетплейса `tessera` (`.claude-plugin/marketplace.json`, git-источники formular
и mattpocock) и проверка при запуске навыка с отказом при отсутствии. Первый механизм
создал цикл: установка tessera требует плагины formular, formular ссылается на tessera.
Мотивация — в proposal.md («Why»).

Ограничение: схема каталога маркетплейса (Claude Code и ZCode читают один файл) не имеет
признака «опциональный плагин» — запись в каталоге всегда часть поставки маркетплейса.

## Goals / Non-Goals

**Goals:**

- Разорвать зависимость поставки tessera от маркетплейсов-источников на стороне каталога.
- Сохранить работоспособность навыков без внешних плагинов и внятный отказ при их отсутствии.

**Non-Goals:**

- Правки репозитория formular — обратная сторона цикла устраняется его собственным
  изменением.
- Новый инструмент проверки зависимостей: проверка остаётся текстом шага навыка.
- Закрепление версий зависимостей в каталоге: версии живут в маркетплейсах-источниках.

## Decisions

### 1. Удалить записи из каталога, а не помечать опциональными

Схема каталога не даёт пометки «опционально»: любая запись остаётся поставкой маркетплейса
и сохраняет цикл. Альтернатива «второй каталог для зависимостей» добавляет сопровождаемую
сущность, не убирая ребро tessera → formular. Решение: каталог `tessera` несёт только
`tessera-plugin`; зависимости ставятся из маркетплейсов formular и mattpocock напрямую.

### 2. Проверка при запуске — единственный механизм закрытия

Механизм проверки первым шагом навыка сохраняется и становится единственным: при отсутствии
навыков зависимости навык останавливается отказом с инструкцией установки из
маркетплейса-источника. Тексты отказов `workflow-fast` и `workflow-grill` теряют вариант
«запись в каталоге tessera», остаётся только прямой маркетплейс источника.

### 3. Заявление зависимостей остаётся в README плагина

Таблица «зависимость / минимальная версия / источник» в README плагина — место заявления
зависимостей; корневой `README.md` («Что нужно», «Ограничения») и кейсы 1–2 документа
кейсов несут шаги установки. Второго носителя состава зависимостей не заводится.

### 4. Версия плагина — 0.3.0

Состав поставки и тексты навыков меняются — минорный подъём `0.2.0 → 0.3.0` в обоих
манифестах (`.zcode-plugin/plugin.json`, `.claude-plugin/plugin.json`) и записи каталога
по правилу README плагина («Как расширять»). Нарушение совместимости — на уровне команд
установки из каталога, а не поведения плагина; оно покрывается миграцией ниже.

### 5. Профили установки: кейс и скрипт, не записи каталога

«По умолчанию всё» и «выбираю нужные» реализуются документально и скриптом
`scripts/install-plugins.sh`: флаги `--all`, `--backlog`, `--mattpocock-skills`
комбинируются, вызов без флагов печатает справку — паттерн `scripts/bootstrap.sh --help`.
Для харнессов с CLI скрипт выполняет команды установки из маркетплейсов-источников;
для харнессов без CLI (ZCode — desktop-лаунчер) печатает пошаговую инструкцию. Кейс
полного набора в документе кейсов дублирует команды для ручного пути. Альтернативы:
вернуть записи в каталог — возвращает цикл; второй каталог-бандл — дополнительная
сопровождаемая сущность со своим ребром зависимости; только документация — не даёт
«умолчание — всё» одним вызовом.

## Risks / Trade-offs

- [Установившие `backlog@tessera` теряют путь обновления] → миграция ниже: переустановка
  из маркетплейса formular; навыки данных не хранят, потерь состояния нет.
- [Цикл разорван наполовину: formular продолжает ссылаться на tessera] → устраняется
  отдельным изменением в репозитории formular; это изменение свою сторону закрывает
  полностью.
- [Версии зависимостей больше не видны в каталоге tessera] → бейджи версий в корневом
  `README.md` читают манифесты репозиториев-источников напрямую и остаются информационным
  носителем.
- [CLI установки харнессов меняются между версиями] → скрипт остаётся тонким адаптером;
  fallback — печать инструкции и ручной кейс полного набора.

## Migration Plan

1. Удалить записи из `.claude-plugin/marketplace.json`, поднять версии манифестов до 0.3.0,
   обновить документы и тексты навыков (tasks.md).
2. Потребителям: refresh маркетплейса `tessera` — зависимости исчезают из списка установки;
   установившие их через `tessera` переустанавливают из маркетплейсов-источников
   (`/plugin marketplace add united-software-platform/formular`,
   `/plugin install backlog@formular`; аналогично для mattpocock-skills).
3. Откат — возврат коммита: записи каталога восстанавливаются без миграции данных.
