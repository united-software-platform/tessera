# Design

## Context

Полная механика проверена на стенде (2026-11-27, openspec CLI 2.1.1): `openspec init --tools
<список> --scope project` на каталоге с существующим `openspec/config.yaml` **без `--language`**
не трогает конфигурацию, пишет только навыки, повторный запуск ничего не меняет; `--scope global`
кладёт навыки в `$HOME`. Имена харнесов таблицы `HARNESSES` (zcode, codex, gemini, claude,
opencode) — валидные идентификаторы инструментов инициализации. `--language` с существующей
конфигурацией отвергается ошибкой — флаг не передаётся, язык задаёт `context` репозитория.

Дополнительно стенд выявил: флаг `--no-copilot-cloud` **дописывает** в `openspec/config.yaml`
служебную секцию `githubCopilot`. Флаг нужен (без него интерактивный запуск может спросить
про Copilot), поэтому шаг обязан окружить инициализацию снимком конфигурации: снять файл
во временный, выполнить init, вернуть конфигурацию на место — при любом исходе, включая отказ.

## Decisions

1. **Шаг — после лаунчера, до самопроверки.** `register_openspec_skills()`: перечень — имена
   `SELECTED` (найденные, суженные `--harness`); область — `project` для project, `global`
   для user; флаги `--no-animation --no-copilot-cloud`; вокруг инициализации — снимок
   и возврат `openspec/config.yaml` (флаг copilot дописывает секцию, см. Context). Пустой
   перечень — шаг пропущен (харнесы не отобраны, `--skills-dir` не даёт каталогов харнесов).
2. **CLI через mise.** `mise install` затем `mise exec -- openspec init …`; mise отсутствует —
   openspec из PATH; ни того ни другого — предупреждение и продолжение: навыки tessera уже
   поставлены, шаг докладывается повторной настройкой.
3. **`--plugin-only` пропускает шаг.** Режим обещает работу без сети; mise install при
   отсутствующем CLI качает пакет.
4. **Отчёт называет шаг** строкой с перечнем и областью; при пропуске — причиной.
5. **Проверки.** Дымовой прогон вариантов: после прогона области `user` (поддельные признаки
   zcode и claude) утверждаются навыки OpenSpec в `$SETUP2/.agents/skills` и
   `$SETUP2/.claude/skills` и неизменность `openspec/config.yaml` репозитория (сверка
   с фиксацией `HEAD`). CI ставит mise (mise-action) — иначе шаг в прогоне недоступен.
6. **CI.** Этап «Установить mise» (`jdx/mise-action@v2`, ставит закреплённые инструменты)
   перед «Проверки»; перечень проверок по-прежнему несёт `scripts/check.sh`.

Альтернатива — отдельная задача mise `setup:openspec` — отклонена: установка для разработки
осталась бы двумя командами, что и закрывает задача.

## Risks / Trade-offs

- [Инициализация пишет свои каталоги помимо таблицы харнесов (например, zcode — и `.zcode`)]
  → каталоги вне индекса git; поведение принадлежит openspec CLI, настройка передаёт только
  перечень и область.
- [Новая версия CLI изменит поведение init] → CLI закреплён в `mise.toml`; смена версии —
  осознанная правка с повтором стенда.

## Migration Plan

Правка одного шага; контрибьюторам ничего делать не нужно — следующая `mise run setup`
зарегистрирует навыки OpenSpec. Откат — возврат коммита.

Вне рамок: закрепление версий навыков OpenSpec; `--plugin-only` остаётся без openspec.
