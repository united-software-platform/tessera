# Proposal

## Why

Установку tessera сегодня описывают три механизма в четырёх процедурах, и потребитель не
понимает, что и куда ставится: регистрация симлинками через `scripts/bootstrap.sh`, установка
плагином из маркетплейса вручную и `scripts/install-plugins.sh`, который в ZCode ничего
не устанавливает, а в Claude Code отклоняется без `--yes`. При этом «поставлено» не значит
«работает»: шаблоны операций лежат вне плагина и с ним не поставляются, а CLI `backlog` в ZCode
не находит свою поставку. Прожарка с владельцем свела требование к одному: потребитель
запускает один скрипт и ставит нужное в зависимости от харнеса.

## What Changes

- Новый `scripts/install.sh` — единый механизм для всех харнесов: раскладывает источники
  в хранилище `~/.local/share/tessera/`, связывает навыки симлинками с каталогами навыков,
  ставит лаунчер `backlog`. Запускается одной командой без клона либо из клона.
- Профили поставки: только tessera, tessera с backlog, полный набор; по умолчанию — полный.
- Ставится для всех проектов, параметром запуска — в текущий проект. Харнесы скрипт находит сам.
- Повторный запуск обновляет установленное, `--uninstall` убирает созданное, установка
  завершается самопроверкой.
- Шаблоны операций переносятся в плагин (`plugins/tessera-plugin/templates/`); навыки workflow
  сами передают путь к ним, шаблон проекта приоритетнее.
- `scripts/bootstrap.sh` остаётся только локальной настройкой разработчика tessera с двумя
  каталогами регистрации.
- Установка плагином из маркетплейса — нишевая альтернатива ради обновления кнопкой: она
  ставит навыки и правила tessera, а навыки workflow без зависимостей отказывают и называют
  команду скрипта.
- Документы и язык вслед за механизмом: README из двух шагов, пять кейсов, README плагина,
  `CONTRIBUTING.md`, `AGENTS.md`, глоссарий. Версия плагина — 0.4.0.
- **BREAKING**: `scripts/install-plugins.sh` удаляется — его заменяет `scripts/install.sh`.

## Capabilities

### New Capabilities

- `delivery`: единый скрипт поставки — как потребитель его получает, что и куда ставит,
  как выбирает харнесы, как обновляет и удаляет установку; шаблоны операций в составе поставки.

### Modified Capabilities

- `plugin-dependencies`: зависимости ставятся скриптом поставки из репозиториев-источников
  по профилю, а не вручную из маркетплейсов; отказ навыка называет одну команду установки
  и признаёт зависимости по короткому имени; профили установки описаны через скрипт, который
  выполняет установку в любом харнесе, а не печатает инструкцию. Способность вводится
  изменением `optional-plugin-supply` (пока не заархивировано): это изменение опирается на него
  и архивируется после него.

## Impact

- Скрипты: `scripts/install.sh` — новый; `scripts/install-plugins.sh` — удаляется;
  `scripts/bootstrap.sh` — меняет цели регистрации.
- Плагин: `plugins/tessera-plugin/templates/` — шаблоны операций (переносятся из `templates/`
  корня репозитория); навыки `workflow-fast`, `workflow-grill`, `tessera-plugin` — путь
  к шаблонам, отказы, описание зависимостей; версия 0.4.0 в обоих манифестах и записи каталога.
- Документы: `README.md`, `docs/use-cases.md`, `plugins/tessera-plugin/README.md`,
  `CONTRIBUTING.md`, `AGENTS.md`, `GLOSSARY.md`.
- Машина потребителя при установке: `~/.local/share/tessera/`, `~/.agents/skills/`,
  `~/.config/opencode/skills/`, `~/.claude/skills/`, `~/.local/bin/backlog`.
- Репозитории-источники зависимостей (formular, mattpocock/skills) читаются, не меняются.
- Вне рамок: дефекты formular (`backlog link` удалён при живой ссылке на него в лаунчере,
  лаунчер не знает кеш ZCode, обратная ссылка на tessera), нативная Windows, CLI зависимостей,
  которых сегодня нет.
