# Design

## Context

Мотивация — в proposal.md, требования — в дельтах `delivery` и `plugin-dependencies`.

Факты, на которые опирается подход (проверены 2026-11-23):

- Состав плагинов. `tessera-plugin`, `backlog` (formular) и `mattpocock-skills` несут только
  навыки; у `backlog` ещё CLI. Ни hooks, ни commands, ни MCP ни в одном нет.
- Каталоги навыков. `~/.agents/skills/` читают ZCode, Codex и Gemini CLI; Claude Code —
  `~/.claude/skills/`; OpenCode — `~/.config/opencode/skills/`. Симлинки читаются.
- CLI харнесов для установки плагинов: у Claude Code документирован, у Codex экспериментальный,
  у ZCode не документирован (вход под node), в OpenCode и Gemini неприменим.
- CLI `backlog` находит свою поставку через `BACKLOG_HOME`, опрос `claude plugin list` или кеш
  Claude Code; кеш ZCode он не знает. Подкоманды `backlog link` в 1.4.0 нет.
- `backlog generate` берёт каталог шаблонов из `--templates`, иначе `BACKLOG_TEMPLATES`, иначе
  `templates/` проекта; флаг сильнее переменной.
- Шаблоны операций лежат в `templates/` корня репозитория — вне плагина.

Ограничение процесса: способность `plugin-dependencies` вводится изменением
`optional-plugin-supply` и пока не заархивирована. Дельта этого изменения содержит `MODIFIED`
для неё, поэтому `optional-plugin-supply` архивируется первым — иначе архивация откажет.

`CONTRIBUTING.md` и `docs/use-cases.md` несут незакоммиченные правки аудита: по GIT-020 они
коммитятся до правок реализации.

## Goals / Non-Goals

**Goals:**

- Один способ установки, который проверяется на машине разработчика целиком, включая CLI
  зависимостей.
- Установка, обновление и удаление — один и тот же скрипт с одним набором параметров.

**Non-Goals:**

- Установка плагинов средствами харнесов.
- Закрепление версий зависимостей и их источников на теги или коммиты.
- Поддержка Windows без bash.
- Исправление дефектов formular.

## Decisions

### 1. Регистрация из хранилища, а не средства харнесов

Скрипт раскладывает источники в хранилище и связывает навыки симлинками. Альтернатива — вызывать
CLI харнесов — отклонена: даёт несколько путей кода, один из них не документирован, два
неприменимы, а `backlog` в ZCode всё равно требует лаунчера. Установка плагином даёт то же
содержание, плюс кнопку обновления и пространство имён; обновление заменяет повторный запуск,
о потерянных коротких именах см. раздел 8.

### 2. Хранилище

```text
~/.local/share/tessera/
  tessera/             клон united-software-platform/tessera
  formular/            клон united-software-platform/formular
  mattpocock-skills/   клон mattpocock/skills
```

Ветка `main`, полные клоны. Источники навыков:

| Компонент | Каталог навыков |
|-----------|-----------------|
| tessera | `tessera/plugins/tessera-plugin/skills/*` |
| backlog | `formular/plugin/backlog/skills/*` |
| mattpocock-skills | `mattpocock-skills/skills/engineering/*`, `mattpocock-skills/skills/productivity/*` |

Запуск из клона устанавливает из хранилища: клон служит только способом получить скрипт,
результат не зависит от его ветки.

### 3. Каталоги навыков и определение харнесов

| Харнес | Признак | Пользовательский каталог | Проектный каталог |
|--------|---------|--------------------------|-------------------|
| zcode | `~/.zcode` | `~/.agents/skills/` | `.agents/skills/` |
| codex | `~/.codex` или `codex` в PATH | `~/.agents/skills/` | `.agents/skills/` |
| gemini | `~/.gemini` или `gemini` в PATH | `~/.agents/skills/` | `.agents/skills/` |
| claude | `~/.claude` или `claude` в PATH | `~/.claude/skills/` | `.claude/skills/` |
| opencode | `~/.config/opencode` или `opencode` в PATH | `~/.config/opencode/skills/` | `.agents/skills/` |

Каталог-цель один на путь: найденные ZCode и Codex дают одну запись `~/.agents/skills/`.
Таблица живёт в скрипте в одном месте. Найденных харнесов нет и путь не передан — скрипт
сообщает об этом и выходит, ничего не меняя.

### 4. Лаунчер `backlog`

```sh
#!/usr/bin/env sh
# Лаунчер backlog — создан скриптом поставки tessera (scripts/install.sh).
export BACKLOG_HOME="${HOME}/.local/share/tessera/formular/plugin/backlog"
exec "${BACKLOG_HOME}/bin/backlog" "$@"
```

Маркерная строка отличает свой лаунчер от чужого. Обёртка, а не симлинк: `bin/backlog` берёт
корень поставки из `$0` и не разрешает ссылки. Лаунчер ставится только с профилем, включающим
backlog. Если `~/.local/bin` вне PATH, отчёт предупреждает об этом. Чужой файл по пути
лаунчера сохраняется как `backlog.bak`.

### 5. Профили и параметры запуска

| Параметр | Действие | Умолчание |
|----------|----------|-----------|
| `--profile full\|backlog\|tessera` | состав установки | `full` |
| `--project` | регистрация в текущем проекте | пользовательские каталоги |
| `--harness zcode,codex,…` | ограничить харнесы | все найденные |
| `--skills-dir <путь>` | дополнительный каталог навыков | — |
| `--yes` | без диалога | диалог при терминале |
| `--uninstall` | удалить созданное | — |
| `-h`, `--help` | справка | — |

`backlog` ставит tessera и backlog, `full` добавляет mattpocock-skills. Диалог читает `/dev/tty`,
поэтому работает и в конвейере `curl | bash`; без терминала скрипт ведёт себя как с `--yes`.

### 6. Повторный запуск и удаление

Установленное состояние выводится из самого хранилища и ссылок: есть клон formular — backlog
выбран. Повторный запуск выполняет `git pull --ff-only` в каждом клоне; клон с незакоммиченными
изменениями пропускается с сообщением. Ссылки пересоздаются, параметры запуска переопределяют
состав и цели. Удаление снимает только ссылки, цель которых лежит в хранилище, свой лаунчер
(по маркеру) и само хранилище; файл состояния не заводится.

### 7. Шаблоны операций в плагине

Шаблоны переезжают в `plugins/tessera-plugin/templates/`; корневой `templates/` удаляется.
Навык workflow действует так: в проекте есть `templates/<операция>.md` — передаёт
`--templates <проект>/templates`; иначе — `--templates` с реальным путём `../../templates`
от своего каталога. Путь разрешается через `realpath`, потому что навык может быть доступен
через симлинк.

### 8. Имена навыков зависимостей

Под регистрацией навыки видны по коротким именам. Навыки workflow зовут зависимости по короткому
имени (`backlog-generate`, `backlog-run`, `grilling`) и признают имя с префиксом плагина
(`/backlog:backlog-generate`, `/mattpocock-skills:grilling`). Отказ называет одну команду —
запуск скрипта поставки.

### 9. `bootstrap.sh` для разработки

Цели: `agents` → `.agents/skills/`, `claude` → `.claude/skills/`, произвольный путь. Цель `zcode`
снята — ZCode читает `.agents/skills/`; при запуске скрипт снимает свои прежние ссылки
из `.zcode/skills/`, чтобы навыки не двоились.

### 10. Маркетплейс — нишевая альтернатива

Каталог маркетплейса остаётся в репозитории без изменений. Документы описывают установку
плагином одним кейсом «обновлять кнопкой» с оговоркой: ставятся навыки и правила tessera,
навыки workflow без зависимостей отказывают и называют команду скрипта.

### 11. Язык глоссария

| Понятие | Вид | Смысл |
|---------|-----|-------|
| Поставка | доменная служба | доставка скриптом установки: хранилище, регистрация навыков, лаунчер CLI зависимостей |
| Установка | доменная служба | поставка плагином из маркетплейса — альтернатива скрипту ради обновления кнопкой |
| Регистрация | доменная служба | связывание навыков с каталогом харнеса симлинками — механизм скрипта поставки и локальной настройки |
| Профиль поставки | объект-значение | состав установки: только tessera, с backlog, полный |
| Хранилище | сущность | локальные клоны источников, на которые ссылаются регистрации |
| Лаунчер | сущность | обёртка CLI зависимости на PATH |
| Зависимость | объект-значение | ставится скриптом по профилю и проверяется при запуске навыка |

### 12. Проверка

Самопроверка скрипта — в конце каждого запуска: каждая ссылка разрешается в `SKILL.md`,
`backlog --help` через лаунчер отвечает успехом. Проверка разработчика — дымовой прогон
в изолированном домашнем каталоге с явным `--skills-dir`, поскольку харнесов там нет.

## Risks / Trade-offs

- [Короткие имена навыков зависимостей сталкиваются с чужими навыками] → чужой элемент
  пропускается и называется в отчёте.
- [27 навыков mattpocock-skills попадают в пользовательский каталог] → состав профиля виден
  в `--help`; профили `tessera` и `backlog` для тех, кому они не нужны.
- [Каталоги навыков харнеса меняются с версией] → таблица в одном месте скрипта;
  для харнеса вне таблицы — `--skills-dir`.
- [Ветка `main` стороннего репозитория меняется без предупреждения] → как раньше в каталоге
  маркетплейса (`ref: main`); откат не предусмотрен.
- [Изолированная проверка не подтверждает, что харнес увидел навыки] → проверка владельца
  после перезапуска сессии харнеса.
- [Изменение опирается на не заархивированное] → порядок архивации зафиксирован; валидатор
  напоминает об этом до архивации `optional-plugin-supply`.

## Migration Plan

1. Правки `CONTRIBUTING.md` и `docs/use-cases.md` начинаются после коммита правок аудита.
2. Потребители ставят tessera одной командой; `scripts/install-plugins.sh` удаляется.
3. Хост владельца: изолированная проверка, затем настоящая установка, затем снятие из ZCode
   плагинов `backlog` и `mattpocock-skills`, установленных из маркетплейсов, — дубли навыков.
   Каждый шаг — по отдельному слову владельца.
4. Откат — `--uninstall`; прежний лаунчер возвращается из `backlog.bak` вручную.
