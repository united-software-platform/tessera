# Design

## Context

Правки сути согласованы прожаркой (grill-with-docs): боль, суть, потребитель, имя и границы —
решения Q1–Q11. Документы поставки (README, About, GLOSSARY, CONTRIBUTING) перестраиваются
под фреймворк; применение правил реализуется расширением каталог-навыка. Рабочее дерево уже
несёт правки документов — apply-фаза сводится к сверке с задачами.

## Goals / Non-Goals

**Goals:**

- Канон сути в назначении README, About и контексте GLOSSARY
- Правила как часть поставки с применением через навыки
- OpenSpec как выбор разработчика

**Non-Goals:**

- Англоязычная адаптация артефактов
- Автозагрузка правил хуками
- Позиционирование механизма поставки как отдельного продукта

## Decisions

- Контекст глоссария переименован в «Инженерный фреймворк tessera»; «поставка» понижена
  до доменной службы (решение прожарки Q7).
- Правила применяются композитом: каталог-навык — общая точка входа, профильные навыки —
  явные ссылки (Q8, Q11). Альтернатива — SessionStart-хуки — отклонена как харнес-специфичная.
- openspec-бейджи убраны из README; класс «стандарт» выведен из легенды бейджей.

## Risks / Trade-offs

- Применение правил зависит от дисциплины навыков: без вызова навыка правило молчит.
  Принято ради универсальности.
- «Минимальность» без числового критерия: граница состава проводится обзором при каждом
  изменении поставки.
