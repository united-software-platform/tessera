# Design

## Context

Мотивация — в `proposal.md`, требования — в дельте `specs/delivery/spec.md`. Здесь только то,
что определяет подход.

- `scripts/install.sh` — один bash-файл без внешних зависимостей, кроме `git` и `curl`.
  Состав установки известен только функциям установки: `collect_skills` заполняет массивы
  навыков из клонов и останавливает скрипт, если клона нет; перечень правил собирает
  `collect_rules`; каталоги назначения — `compute_targets`.
- До установки скрипт завершается ошибкой, если харнесы не найдены и каталог навыков не
  передан; диалог читает `/dev/tty`.
- Хранилище — полные клоны ветки `main`; клона может не быть до первой установки.
- `README.md` перечисляет имена навыков и правил вручную (реестр поставки из TSS-015).

## Goals / Non-Goals

**Goals:**

- Реестр порождается из тех же источников и теми же правилами, что и установка, — и не может
  разойтись с ней.
- Реестр переносим: одинаков для разных домашних каталогов и каталогов запуска.
- `--registry` безопасен: ничего не создаёт, не меняет и не спрашивает.

**Non-Goals:**

- Схема, подпись и проверка подлинности реестра.
- Реестр как средство отката или восстановления установки.
- Описание внутреннего устройства клонов хранилища.

## Decisions

### 1. JSON собирается в bash, без `jq`

Скрипт обязан обходиться bash, git и curl, поэтому реестр собирается функциями самого скрипта:
экранирование строки (`\`, `"`, управляющие символы) и сборка массивов и объектов. Все имена,
пути и URL в реестре — из таблиц `COMPONENTS` и `HARNESSES`, имён файлов клонов и параметров
запуска; единственный свободный текст — названия правил из заголовков их файлов, поэтому
экранирование обязательно, а не для порядка.

Альтернатива: требовать `jq` (новая зависимость ради одной команды; на чистой системе
её нет — отклонено).

### 2. Один сборщик — для печати и для записи

Функция строит реестр в переменную. `--registry` печатает её, установка записывает её
в файлы. Второй сборщик не заводится: напечатанный реестр и записанный совпадают по составу.

### 3. Реестр описывает установку этих же параметров

`--registry` проходит тот же путь, что установка, до первого изменения на диске: разбирает
параметры, находит харнесы, вычисляет каталоги назначения, читает перечень правил — и
останавливается перед получением источников и диалогом. Поэтому `--profile`, `--project`,
`--harness`, `--skills-dir` и `--rules` действуют и на реестр.

Следствия, фиксируемые явно:

- `--registry` не спрашивает: умолчания берутся как при `--yes`; сам `--yes` на него
  не влияет.
- Ошибка параметров при `--registry` — та же, что при установке: код `2`. С `--uninstall`
  флаг не сочетается: напечатать реестр, ничего не меняя, и удалить поставку в одном запуске
  нельзя.
- Если харнесы не найдены и каталог не передан, реестр всё равно печатается с пустым перечнем
  каталогов навыков и предупреждением на стандартном выводе ошибок: цель команды — показать,
  что произошло бы, а не остановить потребителя.

Альтернатива: печатать реестр только когда установка возможна (скрывала бы от потребителя
главный интерес — увидеть состав до подготовки машины — отклонено).

### 4. Пути относительны: `~` для машины, корень проекта для проекта

Пути в домашнем каталоге записываются от `~`, пути проекта — от его корня. Абсолютный путь
хранится только там, где без него нельзя сверить источник, — нигде: источники тоже лежат
в хранилище под `~`. Сравнение двух реестров, напечатанных на разных машинах, показывает
различия состава, а не различия имён пользователей.

Альтернатива: абсолютные пути (реестр привязан к машине и бесполезен для сверки с чужим
репозиторием — отклонено).

### 5. Без источников реестр частичен, с пометкой в самом документе

Перечни навыков и правил берутся из клонов. Пока клона нет, реестр печатает всё остальное
и помечает недоступные перечни полем статуса, а не пропускает их молча. Частичный реестр —
рабочий результат с кодом `0`, а не ошибка: уровни поставки, цели и совпадения видны и без
клонов. Потребитель узнаёт о неполноте из документа, а не из кода возврата.

Альтернатива: код возврата, отличный от `0`, для частичного реестра (ломал бы конвейер
`curl | bash -s -- --registry | jq` и вынуждал ставить tessera, чтобы узнать её состав —
отклонено).

### 6. Факт установки — тот же реестр плюс время

Установка записывает реестр в `registry.json` в хранилище, а с `--project` — ещё и
в `.tessera/registry.json`. Файл в хранилище описывает поставку машины в целом, файл
в проекте — то, что поставлено в этот проект. Запись идёт после самопроверки: реестр
фиксирует состоявшуюся установку.

Альтернатива: отдельный формат факта (вторая схема ради различия в двух полях — отклонено).

### 7. README называет команду, а не перечисляет имена

Перечни имён навыков и правил уходят из `README.md` по [DGN-011](../../../plugins/tessera-plugin/rules/project-docs-rules.md#нормы-и-перечни-инструментов-dgn-010011):
перечень, который выдаёт инструмент, документ называет командой. На месте ручной таблицы
уровней (решение владельца 2026-11-24) — сокращённый пример реального вывода `--registry`
с командой для полного; правила совпадений остаются — это объяснение, а не перечень.

Альтернатива: вести перечень руками и сверять проверкой (вторая копия, которую надо не
забывать обновлять — отклонено).

## Risks / Trade-offs

- [Реестр — обещание формата: потребитель строит на нём разбор] → Поле версии реестра
  в документе; изменение состава полей — отдельным изменением с повышением версии.
- [Частичный реестр принят за полный] → Статус перечня явный в документе; сценарии дельты
  проверяют оба состояния.
- [Названия правил — свободный текст в JSON] → Обязательное экранирование всех строковых
  значений; проверка `python3 -m json.tool` в задачах.
- [`--registry` при ненайденных харнесах не останавливает потребителя] → Предупреждение
  на стандартном выводе ошибок; каталоги назначения в реестре пусты — видно сразу.
- [Реестр в хранилище описывает последнюю установку, а не все] → Документировано: каждая
  установка переписывает файл.

## Migration Plan

1. Реализовать `--registry` и запись реестра, проверить в поддельных домашних каталогах
   и проектах — `tasks.md`.
2. Перевести `README.md` на команду; обновить кейсы, `CONTRIBUTING.md` и глоссарий.
3. После слияния consumers получают реестр командой; ручной перечень в `README.md`
   исчезает той же правкой.

Откат: изменение обратно совместимо — установки без `--registry` меняются только появлением
`registry.json`.
