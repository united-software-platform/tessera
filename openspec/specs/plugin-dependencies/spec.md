# plugin-dependencies Specification

## Purpose

Опциональная поставка внешних плагинов-зависимостей tessera: каталог маркетплейса несёт только
собственный плагин, зависимости устанавливает разработчик из маркетплейсов-источников,
навыки проверяют зависимость при запуске.

## Requirements


### Requirement: Каталог несёт только собственный плагин

Каталог маркетплейса `tessera` SHALL поставлять только собственный плагин `tessera-plugin`
и MUST NOT нести записи внешних плагинов-зависимостей: их присутствие создаёт циклическую
зависимость поставки tessera от маркетплейсов-источников.

#### Scenario: Потребитель добавляет маркетплейс

- **WHEN** потребитель добавляет маркетплейс `tessera` в харнес
- **THEN** каталог предлагает к установке только `tessera-plugin`; записей `backlog`
  и `mattpocock-skills` в нём нет

### Requirement: Зависимости устанавливаются разработчиком

Внешние плагины-зависимости — опциональная поставка: каждая SHALL ставиться скриптом поставки
из репозитория-источника отдельным компонентом состава, который разработчик задаёт перечнем
компонентов. Состав без зависимостей MUST обходиться без них.

#### Scenario: Установка без зависимостей

- **WHEN** потребитель устанавливает состав из одного tessera
- **THEN** установка завершается успешно, а навыки без внешних зависимостей работают полностью

#### Scenario: Нужен workflow-навык

- **WHEN** разработчику нужны навыки `workflow-fast` или `workflow-grill`
- **THEN** он задаёт состав с компонентом formular (для прожарки — ещё mattpocock-skills),
  и скрипт приносит зависимости из репозиториев-источников formular и mattpocock

#### Scenario: Отдельная установка зависимости

- **WHEN** tessera у потребителя поставлен плагином из маркетплейса
- **THEN** он ставит скриптом поставки одни зависимости — состав без tessera

### Requirement: Навыки проверяют зависимость при запуске

Навык, зависящий от внешнего плагина, SHALL первым шагом проверять доступность навыков
зависимости — по короткому имени и по имени с префиксом плагина — и при их отсутствии
останавливаться отказом, называющим одну команду запуска скрипта поставки с составом,
включающим недостающие компоненты. Отказ SHALL предупреждать, что состав задаётся точно,
и называть команду, печатающую поставленный состав.

#### Scenario: Зависимость отсутствует

- **WHEN** владелец вызывает `workflow-fast` без установленного плагина backlog
- **THEN** навык останавливается отказом с командой запуска скрипта поставки, включающей
  компонент formular

#### Scenario: Зависимость установлена

- **WHEN** владелец вызывает `workflow-fast` с установленным плагином backlog
- **THEN** проверка проходит и навык продолжает работу без вопросов об установке

#### Scenario: Состав с прочими компонентами

- **WHEN** владелец выполнил команду отказа, вписав в перечень и прочие поставленные компоненты
- **THEN** недостающий компонент добавлен, а поставленные остались на месте
