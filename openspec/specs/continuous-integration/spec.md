# continuous-integration Specification

## Purpose

Автоматический прогон проверок репозитория tessera на GitHub Actions при каждой правке
и связь состояния этих прогонов с читателем через бейдж `README.md`.

## Requirements

### Requirement: Проверки запускаются на push и pull request

Репозиторий SHALL нести workflow GitHub Actions `.github/workflows/ci.yml`, который запускает
прогон проверок репозитория при push в ветку `main` и при открытии, переоткрытии или обновлении
pull request.

#### Scenario: Push в main

- **WHEN** в ветку `main` поступает push
- **THEN** запускается прогон проверок на отправленном состоянии

#### Scenario: Pull request

- **WHEN** pull request открыт, переоткрыт или получил новые коммиты
- **THEN** запускается прогон проверок на состоянии слияния pull request с `main`

#### Scenario: Проверки не пройдены

- **WHEN** проверки завершились ошибкой
- **THEN** прогон помечается неудачным

### Requirement: Скрипт проверок передаёт результат кодом возврата

Скрипт проверок `scripts/check.sh` SHALL исполнять проверки по порядку, называть каждую перед
запуском и завершаться кодом `0`, когда все проверки пройдены.

#### Scenario: Все проверки пройдены

- **WHEN** каждая проверка завершилась успешно
- **THEN** скрипт завершается с кодом `0`

#### Scenario: Проверка не пройдена

- **WHEN** очередная проверка завершилась с ошибкой
- **THEN** скрипт называет непройденную проверку, завершается ненулевым кодом и не запускает
  следующие

### Requirement: Перечень проверок не дублируется

Перечень проверок SHALL жить только в скрипте: workflow SHALL вызывать скрипт, а не повторять
команды, а раздел «Проверки» `CONTRIBUTING.md` SHALL называть скрипт одной командой.

#### Scenario: В скрипт добавлена проверка

- **WHEN** в скрипт добавлена новая проверка
- **THEN** прогон исполняет её без правки workflow и `CONTRIBUTING.md`

#### Scenario: Локальный запуск

- **WHEN** правящий репозиторий запускает `scripts/check.sh`
- **THEN** исполняются те же проверки, что и в прогоне

### Requirement: Прогон обходится без секретов

Прогон SHALL обходиться без секретов репозитория, а токен SHALL иметь только право чтения
содержимого. Из сети прогону SHALL быть достаточно чтения публичных репозиториев GitHub.

#### Scenario: Секреты не заданы

- **WHEN** в репозитории не задано ни одного секрета, а проверяемое состояние проходит проверки
- **THEN** прогон завершается успешно

#### Scenario: Pull request из форка

- **WHEN** pull request поступает из форка
- **THEN** его прогон запускается без прав на запись в репозиторий

### Requirement: Дымовые прогоны ставят tessera из проверяемого состояния

Дымовые прогоны установки SHALL ставить tessera из фиксации `HEAD` каталога репозитория,
из которого запущен скрипт проверок, а зависимости — из их репозиториев, как их ставит
скрипт поставки.

#### Scenario: Pull request меняет содержимое плагина

- **WHEN** в pull request изменены навыки, правила или шаблоны плагина так, что установка
  ломается
- **THEN** прогон этого pull request завершается ошибкой ещё до слияния

#### Scenario: Зависимости — из репозиториев

- **WHEN** дымовой прогон исполняется
- **THEN** formular и mattpocock-skills клонируются из своих репозиториев на GitHub

### Requirement: README несёт бейдж состояния проверок

Блок бейджей `README.md` SHALL нести бейдж состояния прогонов workflow на ветке `main`.
Значение SHALL читаться из прогонов GitHub Actions, а не записываться в разметку.

#### Scenario: Прогоны на main пройдены

- **WHEN** последний прогон на `main` завершился успешно
- **THEN** бейдж показывает «passing»

#### Scenario: Прогон на main не пройден

- **WHEN** последний прогон на `main` завершился ошибкой
- **THEN** бейдж показывает «failing»

#### Scenario: Бейдж назван в карте бейджей

- **WHEN** бейдж состояния добавлен в блок бейджей
- **THEN** легенда `CONTRIBUTING.md` называет его класс и цвет, а карта бейджей — источник
  значения, режим и цель ссылки
