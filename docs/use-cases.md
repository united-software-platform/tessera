# Кейсы tessera

Задачи применяющего систему за пределами основного пути `README.md`, записанные от первого
лица. Основной путь — установка скриптом поставки для всех проектов; здесь — установка только
в один проект, состав поставки до установки, подключение части правил, поставка без
зависимостей, смена состава, обновление кнопкой и применение навыков плагина с примерами
вызовов.

## Кейс 1. Хочу поставить tessera только в один проект

**Когда.** Я хочу пользоваться tessera в одном репозитории и не менять пользовательские
каталоги навыков — например, пробую фреймворк или работаю с общими настройками харнеса.

**Что делаю.** Запускаю скрипт установки из корня проекта с областью `project`:

```bash
curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --scope project
```

Скрипт показывает найденные харнесы и план установки, как при обычной установке, но ссылки
на навыки создаёт в каталогах навыков проекта — `.agents/skills/`, `.claude/skills/` и других
по таблице харнесов. Источники по-прежнему лежат в хранилище `~/.local/share/tessera/`, поэтому
обновление — повторный запуск из корня проекта, удаление — тот же запуск с `--uninstall`.

**Что получаю.** Навыки tessera в одном проекте: ссылки лежат в его каталогах навыков,
пользовательские каталоги не меняются, харнес видит навыки после перезапуска сессии
в этом проекте. Ссылки ведут в хранилище моей машины, поэтому в репозиторий проекта я их
не коммичу. Правила — наоборот: их копии в `.tessera/rules/` и секция в `AGENTS.md`
переносимы, я коммичу их вместе с проектом, и правила действуют у всех, кто его скопировал.

## Кейс 2. Хочу узнать состав поставки до установки

**Когда.** Я присматриваю tessera к своему репозиторию и хочу заранее знать, какие имена
и пути появятся в проекте и на машине — и с чем из уже установленного они могут совпасть.

**Что делаю.** Прошу скрипт напечатать реестр поставки — без установки:

```bash
curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --registry
```

Реестр — JSON: компоненты с источниками и путями хранилища, навыки, правила, секция `AGENTS.md`
и лаунчер; каждая запись — имя, тип (`symlink`, `copy`, `section`, `wrapper`), целевой путь
и источник. Параметры работают те же: с `--scope project`, `--components` и `--rules` я увижу
цели конкретного проекта, состав и выбранные правила. Разбираю фильтром — например, только
целевые пути:

```bash
... | jq -r '.skills[].target, .rules[].target'
```

**Что получаю.** JSON со всем, что создала бы установка с этими параметрами; диск не меняется.
До первой установки хранилища нет — реестр печатается частичным: уровни поставки описаны,
а перечни навыков и правил помечены как недоступные до получения источников. После установки
тот же реестр лежит файлом `registry.json` в хранилище, а в области `project` — ещё и в
`.tessera/` проекта: факт того, что именно поставлено.

## Кейс 3. Хочу подключить к проекту только часть правил

**Когда.** Мне нужны не все восемь правил tessera — например, только документация и git-процесс,
а правила архитектуры в этом проекте лишние.

**Что делаю.** Передаю перечень правил параметром `--rules` — имена файлов без `.md` через
запятую:

```bash
curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --scope project --rules documentation-rules,git-rules
```

Перечень правил с названиями печатает диалог установки, если `--rules` не задан: в нём я
называю номера или имена через запятую, `all`, `none` или оставляю умолчание — прежний
перечень проекта, а без копий — все правила. Неизвестное имя в `--rules` скрипт отвергает,
называя доступные правила. Подключены будут ровно названные: правила по ссылкам внутри себя
не подтягиваются, а ссылка подключённого правила на неподключённое называется в отчёте —
по ней правило можно добавить.

**Что получаю.** В `.tessera/rules/` лежат копии только названных правил, в `AGENTS.md` — секция
со штампом поставки и перечнем. Состав можно менять: повторный запуск с другим `--rules`
добавляет, обновляет и снимает копии под новый перечень; правленая вручную копия исключаемого
правила останавливает установку, чтобы правка не пропала. Вернуть все правила — запуск с
`--rules all`, отключить правила проекта, оставив навыки, — `--rules none`.

## Кейс 4. Хочу поставить tessera без зависимостей

**Когда.** Мне нужны навыки и правила tessera, а workflow-навыки с их зависимостями — нет:
например, плагин formular потребляет tessera, и тащить в поставку его собственный плагин
backlog нельзя — это цикл поставки.

**Что делаю.** Называю состав явно — один компонент:

```bash
curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --components tessera
```

**Что получаю.** Только tessera: навыки `project-docs` и `tessera-plugin`, правила и шаблоны
операций. Клона formular нет, команда `backlog` не ставится, python3 не нужен; навыки
workflow при вызове остановятся отказом с командой установки состава. Состав ставится точно:
если раньше стояло больше, лишнее снято этим же запуском.

## Кейс 5. Хочу сменить состав поставки

**Когда.** Состав задач изменился: понадобился workflow — или, наоборот, зависимость стала
лишней, и я хочу убрать её из поставки.

**Что делаю.** Повторный запуск с новым перечнем `--components`: состав ставится точно —
недостающие компоненты добавляются, не названные снимаются.

```bash
curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --components tessera,formular
```

**Что получаю.** Состав ровно перечню. В терминале снимаемое показывается в плане до
подтверждения, в отчёте — строка «Снято при смене состава» с числом снятых ссылок; клоны,
лаунчер и связи навыков обновляются без повторных вопросов. Правила и секция `AGENTS.md`
в проекте не трогаются вне проектной области.

## Кейс 6. Хочу обновлять tessera кнопкой

**Когда.** Мой харнес поддерживает плагины с маркетплейсами, и я хочу получать обновления
tessera кнопкой, не запуская скрипт установки.

**Что делаю.** Добавляю маркетплейс `tessera` адресом репозитория
`https://github.com/united-software-platform/tessera.git` и устанавливаю **Tessera Plugin**.
В ZCode это **Plugin Marketplace → Add → Add Plugin Marketplace**, затем **Personal → tessera**;
в Claude Code — команды `/plugin marketplace add united-software-platform/tessera`
и `/plugin install tessera-plugin@tessera`.

**Что получаю.** Навыки и правила tessera как установленный плагин; обновление — refresh
маркетплейса и кнопка Update в разделе плагина.

**Если нужен workflow-навык.** Плагин ставит только навыки и правила tessera — зависимостей
в нём нет, поэтому `workflow-fast` и `workflow-grill` останавливаются отказом с командой
установки. Зависимости приносит скрипт поставки:

```bash
curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --components formular,mattpocock-skills
```

Состав без tessera не ставит его второй раз: навыки и правила остаются плагину, обновляемому
кнопкой, а скрипт приносит только зависимости.

## Кейс 7. Хочу проверить и поправить документы проекта

**Когда.** `README.md` и `CONTRIBUTING.md` уже написаны, и я хочу убедиться, что они соответствуют
норме документов проекта, — или завести недостающий документ.

**Что делаю.** Прошу харнес выполнить навык `project-docs`:

```text
Выполни навык project-docs: проверь README.md и CONTRIBUTING.md по DGN-норме.
```

Навык читает норму, находит документы и применяет каждое правило. Для правки — тем же навыком:
«выровняй документы по отчёту аудита»; изменения вносятся только по перечню, который я подтвердил.

**Что получаю.** Отчёт аудита: проверенные документы, вывод по отсутствующим и таблица
расхождений «расхождение / код / место»; после правки — документы, прошедшие повторный аудит.

## Кейс 8. Хочу быстро пройти от требования до ветки

**Когда.** Требование сформулировано текстом, прожарка не нужна — нужен быстрый ход до ветки
изменений; в составе поставки есть formular.

**Что делаю.** Одним вызовом прошу харнес запустить навык:

```text
Запусти workflow-fast: добавить в выгрузку фильтр по складу.
```

Навык строит предмет-адрес прогона, предлагает целевой репозиторий из `origin`, показывает
собранный вызов порождения беклога и передаёт исполнение без повторных вопросов.

**Что получаю.** Порождённый беклог операции `workflow-fast` и исполнение до ветки изменений;
единственный стоп-вопрос — перед созданием задачи на GitHub.

## Кейс 9. Хочу прогреть требование прожаркой

**Когда.** Решение новое или рискованное, и до реализации его нужно раскритиковать; в составе
поставки есть formular и mattpocock-skills.

**Что делаю.** Прошу харнес запустить навык с требованием:

```text
Запусти workflow-grill: сменить хранение сессий на Redis.
```

**Что получаю.** Порождённый беклог операции `workflow` с прожаркой: критика решения
входит в исполнение, ветка изменений появляется после неё.
