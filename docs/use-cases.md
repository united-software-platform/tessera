## Кейс 1. Хочу ставить обновляемым плагином в ZCode

**Когда.** Я работаю в ZCode и хочу получать обновления tessera кнопкой, не обновляя клон
вручную.

**Что делаю.** Открываю **Plugin Marketplace → Add → Add Plugin Marketplace** и вставляю
адрес репозитория: `https://github.com/united-software-platform/tessera.git`. Затем
в **Personal → tessera** устанавливаю **Tessera Plugin**. Зависимости — опциональная
поставка: **Backlog (formular)** для workflow-навыков и **Matt Pocock Skills** для прожарки
в `workflow-grill` я ставлю сам, добавив их маркетплейсы-источники formular и mattpocock;
полный путь одним списком — кейс 3.

**Что получаю.** Навыки и правила tessera как установленный плагин; обновление — refresh
маркетплейса и кнопка Update в разделе плагина.

## Кейс 2. Хочу ставить обновляемым плагином в Claude Code

**Когда.** Я работаю в Claude Code и хочу ставить tessera штатными командами плагинов.

**Что делаю.** В REPL выполняю:

```text
/plugin marketplace add united-software-platform/tessera
/plugin install tessera-plugin@tessera

# зависимости — опционально, из маркетплейсов-источников:
/plugin marketplace add united-software-platform/formular
/plugin install backlog@formular
/plugin marketplace add mattpocock/skills
/plugin install mattpocock-skills@mattpocock
```

**Что получаю.** Навыки tessera и backlog как установленные плагины Claude Code; обновление —
refresh маркетплейса и Update в деталях плагина.

## Кейс 3. Хочу поставить tessera полным набором

**Когда.** Мне нужны все workflow-навыки вместе с прожаркой, и я хочу пройти установку одним
путём, не выбирая зависимости по частям.

**Что делаю.** Ставлю tessera-plugin из маркетплейса tessera и обе зависимости
из маркетплейсов-источников — команды одним блоком:

```text
/plugin marketplace add united-software-platform/tessera
/plugin install tessera-plugin@tessera
/plugin marketplace add united-software-platform/formular
/plugin install backlog@formular
/plugin marketplace add mattpocock/skills
/plugin install mattpocock-skills@mattpocock
```

Либо запускаю скрипт профилей установки — в харнесе с CLI он выполнит те же команды,
без CLI напечатает пошаговую инструкцию:

```bash
scripts/install-plugins.sh --all
```

**Что получаю.** Полный набор: навыки и правила tessera, беклоги операций и прожарку
`grilling`; выборочные профили — флагами `--backlog` и `--mattpocock-skills`, перечень
печатает `scripts/install-plugins.sh --help`.

## Кейс 4. Хочу подключить навыки в другой проект

**Когда.** Мой харнес не поддерживает плагины или я хочу пользоваться навыками tessera
в другом репозитории без установки плагина.

**Что делаю.** Передаю `scripts/bootstrap.sh` путь к каталогу навыков моего проекта — скрипт
создаст симлинки на `plugins/tessera-plugin/skills/`:

```bash
<путь-к-клону-tessera>/scripts/bootstrap.sh <каталог-навыков-моего-проекта>
```

**Что получаю.** Навыки tessera в своём проекте как ссылки на единый источник клона; обновление —
`git pull` в клоне.

## Кейс 5. Хочу проверить и поправить документы проекта

**Когда.** `README.md` и `CONTRIBUTING.md` уже написаны, и я хочу убедиться, что они соответствуют
норме документов проекта, — или завести недостающий документ.

**Что делаю.** Прошу харнес выполнить навык `project-docs`:

```text
Выполни навык project-docs: проверь README.md и CONTRIBUTING.md по DGN-норме.
```

Навык читает норму, находит документы и применяет каждое правило. Для правки — тем же навыком:
«выровняй документы по отчёту аудита»; изменения вносятся только по перечню, который я подтвердил.

**Что получаю.** Отчёт аудита: проверенные документы, вывод по отсутствующим и таблица
расхождений «расхождение / код / место»; после правки — документы, прошедшие повторный аудит.

## Кейс 6. Хочу быстро пройти от требования до ветки

**Когда.** Требование сформулировано текстом, прожарка не нужна — нужен быстрый ход до ветки
изменений; навыки плагина backlog установлены.

**Что делаю.** Одним вызовом прошу харнес запустить навык:

```text
Запусти workflow-fast: добавить в выгрузку фильтр по складу.
```

Навык строит предмет-адрес прогона, предлагает целевой репозиторий из `origin`, показывает
собранный вызов порождения беклога и передаёт исполнение без повторных вопросов.

**Что получаю.** Порождённый беклог операции `workflow-fast` и исполнение до ветки изменений;
единственный стоп-вопрос — перед созданием задачи на GitHub.

## Кейс 7. Хочу прогреть требование прожаркой

**Когда.** Решение новое или рискованное, и до реализации его нужно раскритиковать; навыки
плагинов backlog и mattpocock-skills установлены.

**Что делаю.** Прошу харнес запустить навык с требованием:

```text
Запусти workflow-grill: сменить хранение сессий на Redis.
```

**Что получаю.** Порождённый беклог операции `workflow` с прожаркой: критика решения
входит в исполнение, ветка изменений появляется после неё.
