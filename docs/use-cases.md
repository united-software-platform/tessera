## Кейс 1. Хочу поставить tessera только в один проект

**Когда.** Я хочу пользоваться tessera в одном репозитории и не менять пользовательские
каталоги навыков — например, пробую фреймворк или работаю с общими настройками харнеса.

**Что делаю.** Запускаю скрипт установки из корня проекта с параметром `--project`:

```bash
curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --project
```

Скрипт спрашивает профиль и показывает найденные харнесы, как при обычной установке, но ссылки
на навыки создаёт в каталогах навыков проекта — `.agents/skills/`, `.claude/skills/` и других
по таблице харнесов. Источники по-прежнему лежат в хранилище `~/.local/share/tessera/`, поэтому
обновление — повторный запуск из корня проекта, удаление — тот же запуск с `--uninstall`.

**Что получаю.** Навыки tessera в одном проекте: ссылки лежат в его каталогах навыков,
пользовательские каталоги не меняются, харнес видит навыки после перезапуска сессии
в этом проекте. Ссылки ведут в хранилище моей машины, поэтому в репозиторий проекта я их
не коммичу.

## Кейс 2. Хочу обновлять tessera кнопкой

**Когда.** Мой харнес поддерживает плагины с маркетплейсами, и я хочу получать обновления
tessera кнопкой, не запуская скрипт установки.

**Что делаю.** Добавляю маркетплейс `tessera` адресом репозитория
`https://github.com/united-software-platform/tessera.git` и устанавливаю **Tessera Plugin**.
В ZCode это **Plugin Marketplace → Add → Add Plugin Marketplace**, затем **Personal → tessera**;
в Claude Code — команды `/plugin marketplace add united-software-platform/tessera`
и `/plugin install tessera-plugin@tessera`.

**Что получаю.** Навыки и правила tessera как установленный плагин; обновление — refresh
маркетплейса и кнопка Update в разделе плагина.

**Если нужен workflow-навык.** Плагин ставит только навыки и правила tessera — зависимостей
в нём нет, поэтому `workflow-fast` и `workflow-grill` останавливаются отказом с командой
установки. Зависимости приносит скрипт поставки:

```bash
curl -fsSL https://raw.githubusercontent.com/united-software-platform/tessera/main/scripts/install.sh | bash -s -- --profile full
```

Скрипт ставит и tessera: его навыки станут видны по коротким именам рядом с плагиновыми.
Чтобы остаться при одном экземпляре, плагин я снимаю.

## Кейс 3. Хочу проверить и поправить документы проекта

**Когда.** `README.md` и `CONTRIBUTING.md` уже написаны, и я хочу убедиться, что они соответствуют
норме документов проекта, — или завести недостающий документ.

**Что делаю.** Прошу харнес выполнить навык `project-docs`:

```text
Выполни навык project-docs: проверь README.md и CONTRIBUTING.md по DGN-норме.
```

Навык читает норму, находит документы и применяет каждое правило. Для правки — тем же навыком:
«выровняй документы по отчёту аудита»; изменения вносятся только по перечню, который я подтвердил.

**Что получаю.** Отчёт аудита: проверенные документы, вывод по отсутствующим и таблица
расхождений «расхождение / код / место»; после правки — документы, прошедшие повторный аудит.

## Кейс 4. Хочу быстро пройти от требования до ветки

**Когда.** Требование сформулировано текстом, прожарка не нужна — нужен быстрый ход до ветки
изменений; поставлен профиль `backlog` или полный.

**Что делаю.** Одним вызовом прошу харнес запустить навык:

```text
Запусти workflow-fast: добавить в выгрузку фильтр по складу.
```

Навык строит предмет-адрес прогона, предлагает целевой репозиторий из `origin`, показывает
собранный вызов порождения беклога и передаёт исполнение без повторных вопросов.

**Что получаю.** Порождённый беклог операции `workflow-fast` и исполнение до ветки изменений;
единственный стоп-вопрос — перед созданием задачи на GitHub.

## Кейс 5. Хочу прогреть требование прожаркой

**Когда.** Решение новое или рискованное, и до реализации его нужно раскритиковать; поставлен
полный профиль — с backlog и mattpocock-skills.

**Что делаю.** Прошу харнес запустить навык с требованием:

```text
Запусти workflow-grill: сменить хранение сессий на Redis.
```

**Что получаю.** Порождённый беклог операции `workflow` с прожаркой: критика решения
входит в исполнение, ветка изменений появляется после неё.
