# Правила репозитория tessera

**Предмет:** разработка продукта — уровень работы над предметом: как этот предмет создаётся, правила и процесс.

Точка входа инструкций для агентов, работающих в репозитории: перечень правил, лежащих в плагине
`plugins/tessera-plugin/rules/`. Правила читаются из плагина любым харнесом по ссылкам этого
файла; навыки регистрируются локальной настройкой контрибьютора — см.
[Локальная настройка](#локальная-настройка).

## Предметы описания

Репозиторий tessera — предмет «разработка продукта»: работа над продуктом, его правила
и процесс. Правила и навыки плагина — содержание продукта: их описания принадлежат предмету
«продукт», объявляют его канонической строкой и лежат в `plugins/tessera-plugin/`.

Для работы над репозиторием правила плагина приняты как нормы — их перечень в разделах
«Правила кода» и «Процесс разработки» ниже. Правка правила или навыка плагина — изменение
продукта: готовится изменением OpenSpec и сопровождается повышением версии плагина.
Нормы предмета описания — [PLG-001](./plugins/tessera-plugin/rules/software-class-rules.md#предмет-описания-plg-001002)
и [PLG-003](./plugins/tessera-plugin/rules/software-class-rules.md#объявление-предмета-plg-003004).

## Правила кода

Перед выполнением любой задачи агент обязан полностью прочитать все правила, перечисленные ниже.

- [Документация](./plugins/tessera-plugin/rules/documentation-rules.md) — язык, формат Markdown, структура, версионирование документов.
- [Чтение документов](./plugins/tessera-plugin/rules/reading-rules.md) — гейт чтения, запрещённые каталоги, границы контекста задачи.
- [Окружение](./plugins/tessera-plugin/rules/environment.md) — единый стандарт: mise — единственный менеджер (инструменты, задачи, демоны сервисов), фиксированные порты и паттерн переменных.
- [Чистая архитектура](./plugins/tessera-plugin/rules/clean-architecture.md) — направление зависимостей между слоями, состав слоёв, SOLID, модульная организация.
- [CQRS](./plugins/tessera-plugin/rules/cqrs.md) — разделение контрактов чтения и записи, принадлежность контрактов слоям.
- [Domain Driven Design](./plugins/tessera-plugin/rules/ddd.md) — единый язык, ограниченный контекст, агрегат, сущность, объект-значение, доменное событие.
- [Документы проекта](./plugins/tessera-plugin/rules/project-docs-rules.md) — роли, каркас и голос `README.md`, `CONTRIBUTING.md` и документа кейсов, блок бейджей `README.md`.
- [Нормы классов ПО](./plugins/tessera-plugin/rules/software-class-rules.md) — предмет описания для класса «Плагины»: продукт и разработка продукта, объявление предмета, один предмет на артефакт.

## Локальная настройка

Каталоги регистрации харнесов `.zcode/`, `.claude/` и `.agents/` находятся вне индекса git —
их содержимое контрибьютор создаёт сам под свои инструменты.

1. Настроить харнесы для работы над репозиторием — локальная настройка
   `mise run setup` (`scripts/setup.sh`): навыки плагина связываются с каталогами найденных
   харнесов прямо из рабочего дерева, зависимости (formular, mattpocock-skills) приносятся
   в хранилище `~/.local/share/tessera/`, с formular ставится лаунчер `backlog`. tessera
   для самой себя не ставится, правила не подключаются. Умолчание области — `project`
   (каталоги текущего клона), `--scope user` связывает в пользовательских каталогах,
   `--plugin-only` ограничивает настройку навыками плагина. Параметры и коды возврата
   печатает `scripts/setup.sh --help`; повторный запуск идемпотентен.

1. Разработка репозитория ведётся через OpenSpec; при инициализации набор харнесов
не навязывается. CLI закреплён в `mise.toml` репозитория — `npm:@fission-ai/openspec` 2.1.1,
перекрывает каскад workspace:

```bash
mise exec -- openspec init --tools <список-харнесов> --language ru --scope project
```

Каталог `openspec/` со спецификациями уже лежит в репозитории и от инициализации не зависит.
